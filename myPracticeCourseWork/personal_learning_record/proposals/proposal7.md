# Council Proposal 7

## Explanation of this proposal
*What do you think this proposal might mean? How might it be implemented?*

The proposal suggests shifting the council’s software development approach away from conventional programming (where developers write code line by line in languages like C, Java, or Python) toward low-code/no-code platforms. These platforms let users build applications visually, using drag‑and‑drop interfaces and prebuilt components, which reduces the need for deep coding expertise. This aligns with the council’s broader modernization goals seen across the proposals. Just as Proposal 6 emphasized “digital first” citizen engagement, Proposal 7 emphasizes faster, more accessible development of internal systems. It lowers barriers so non‑technical staff can contribute to building solutions, while professional developers can focus on complex tasks. Agile methodologies: Pairing low-code/no-code with agile project management means projects would be delivered iteratively, with frequent feedback loops and adaptability. This contrasts with traditional “waterfall” approaches, which are slower and less responsive to change. Agile would help the council respond quickly to evolving citizen needs or policy changes. Proposal 7 is about modernizing how the council builds and manages software—making it more accessible, agile, and responsive, while still needing careful oversight to avoid risks. Online platforms become the default way to request services, find information, make payments, or submit forms. The council aims to streamline processes, reduce manual workload, and enhance service accessibility by centralising engagement through modern digital systems. This approach generally reflects a broader move toward cost-efficient, more responsive, and data-driven public service delivery.  Upgrade the council website to host all core services and ensure mobile-friendly design.

Develop or procure a council app with features like service requests, notifications, payments, and account management.

Integrate back-office systems so data flows seamlessly between customer submissions and council departments.

Other communication channels remain available, but are positioned as secondary or fallback options. Audit all current public services and determine how each will be delivered digitally.

Convert paper or telephone-based processes into digital forms, workflows, and self-service tools.

Create a centralised user journey so residents always know where to start. Public awareness campaign: "Your council — now online first."

Support materials such as guides, help videos, FAQs, and in-app onboarding.

Encourage uptake through incentives or soft expectation (e.g., "fastest way to contact us is online"). Maintain phone lines and in-person support for those who need them.

Provide digital skills sessions through libraries, community centres, or partners.

Install public access kiosks or assisted digital service desks where appropriate. Track app usage, response times, user satisfaction, and cost savings.

Gather resident feedback to improve usability and accessibility.

Update features and expand service areas over time as adoption grows. The proposal essentially signals a shift toward digital transformation, where online platforms become the front door to council services. Implementation would require technical capability, redesign of public service pathways, and clear communication — balanced with strong commitments to accessibility and support for digitally excluded groups.
